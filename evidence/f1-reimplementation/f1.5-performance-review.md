# Revisión de rendimiento de F1.5

- **Fecha:** 20 de agosto de 2026.
- **Entorno:** Ubuntu 24.04 sobre WSL2, x86-64, ext4; 4 CPU lógicas,
  Intel Core i7-1185G7; 15 GiB de RAM, sin swap.
- **Compilación:** `cargo build --release --target
  x86_64-unknown-linux-gnu --locked`, sin `target-cpu=native`.
- **Entrada:** plantilla `benchmarks/f1/reference-template.toml`, semilla fija,
  una secuencia y composición A/C/G/T uniforme.
- **Repeticiones:** tres por tamaño; una sonda gemela con `strace 6.8` retrasa
  `renameat2` para observar el pico temporal y exige un árbol idéntico.

Los datos brutos están en `f1.5-benchmark-a.tsv` y
`f1.5-benchmark-b.tsv`. En todas las repeticiones el residuo temporal fue cero,
hubo cuatro ficheros publicados y la sonda observó un provisional no nulo.

## Veredicto

El tiempo, la salida y el RSS crecen de forma compatible con el número de
bases en esta serie. No hay umbral de producto ni perfil que justifique cambiar
la representación ahora. El recorrido materializa referencias completas y las
relee para validación de publicación; es la limitación principal observada, no
una regresión demostrada contra la base F1.4 porque aquella no cerraba F1.5.

El escenario C de 1 Gb queda programado mediante
`./scripts/run-f1-reference-benchmarks.sh C 3` y no se ejecuta en cada cambio,
conforme a DTC-046. No se hacen afirmaciones sobre capacidad ilimitada,
paralelismo ni rendimiento fuera de este entorno.
