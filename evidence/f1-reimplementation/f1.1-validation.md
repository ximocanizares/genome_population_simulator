## Inventario y dependencias

El inventario A/B/C/D y el destino de cada módulo, prueba y dependencia se
conservan en `evidence/f1-reimplementation/retention-map.md`. No se retiró
ninguna dependencia durante F1.1 porque el checkpoint todavía contiene sus
consumidores. `jsonschema` queda señalada para retirada en F1.4.5, después de
eliminar su último consumidor runtime.

Comprobaciones ejecutadas:

```text
cargo metadata --locked --format-version 1 --no-deps
cargo tree --locked -e features --depth 1
cargo audit --no-fetch
```

`cargo metadata` y `cargo tree` terminaron con código 0. La auditoría cargó
1216 avisos, examinó 149 dependencias del `Cargo.lock` y terminó con código 0;
emitió un aviso no bloqueante porque no pudo tomar el bloqueo de la caché local
del índice de crates.io. `cargo audit --locked` no se usa porque esa versión de
la herramienta no admite tal opción.

## Toolchain y puertas

Versiones observadas:

```text
rustc 1.97.1 (8bab26f4f 2026-07-14)
cargo 1.97.1 (c980f4866 2026-06-30)
rustfmt 1.9.0-stable (8bab26f4f6 2026-07-14)
clippy 0.1.97 (8bab26f4f6 2026-07-14)
```

Puertas ejecutadas con resultado verde:

```text
cargo fmt --all -- --check
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
cargo test --workspace --all-targets --all-features --locked
cargo doc --workspace --all-features --no-deps --locked
cargo build --release --workspace --all-features --locked \
  --target x86_64-unknown-linux-gnu
cargo run --locked -- --help
git diff --check
```

La primera ejecución de `--help` mostró la ayuda pero terminó con código 2. La
revisión independiente detectó esa contradicción; F1.1 incorpora ahora una
regresión que exige código 0 y salida no vacía para `--help`, `-h` y
`--version`. La reauditoría por contrato completo fija 54 REQ mediante IDs
exactos: F1.2=4, F1.3=1, F1.4=6, F1.5=22 y F1.6=21. Las pruebas de trazabilidad
rechazan cualquier alta o traslado accidental, no solo una suma incorrecta.

Tras aplicar las correcciones se repitieron todas las puertas: 197 pruebas
all-targets/all-features y dos doctests terminaron sin fallos; formato, Clippy
estricto, documentación, release GNU, metadata, árbol de características,
auditoría sin red y `git diff --check` terminaron con código 0. El aviso de
`cargo audit` sobre el bloqueo de la caché local permanece no bloqueante; el
análisis del `Cargo.lock` sí finalizó.

## Estado de la pausa

F1.1 solo modifica el runtime para que la consulta estándar de ayuda sea una
operación exitosa; no elimina todavía capacidades del checkpoint. Congela la
frontera mínima, prueba que la base sigue siendo recuperable y deja las retiradas
para los hitos que eliminan sus consumidores. La tercera revisión independiente
confirmó H-F11S-01–04 resueltos, recuentos F1/F2 exactos, puertas verdes y
ausencia de trabajo adelantado de F1.2. La pausa queda lista, pero F1.2 no se
inicia sin aprobación explícita.
