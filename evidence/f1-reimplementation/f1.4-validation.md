# Validación de F1.4 reimplementada

> **Estado:** PAUSA-F1.4 aprobada. Q1–Q4 y los hallazgos de las revisiones quinta
> y sexta están corregidos. La séptima revisión no encontró defectos
> funcionales; su única deriva de trazabilidad se corrigió con una regresión
> ejecutable sobre la copia TOML y los gates completos volvieron a pasar.

- **Fecha:** 20 de agosto de 2026.
- **Base publicada:** `3416db4`.
- **Alcance:** F1.4.1–F1.4.5 del plan 0.2; no incluye F1.5.
- **Entorno:** Linux `6.18.33.2-microsoft-standard-WSL2` x86-64 GNU/Linux.
- **Toolchain:** rustc 1.97.1 y Cargo 1.97.1.

## Resultado

F1.4 publica un manifiesto general mínimo `complete` o `failed`. El catálogo es
la única descripción física de cada fichero y los enlaces semánticos usan IDs.
`manifest.json` queda fuera del catálogo porque registrar su propio tamaño y
SHA-256 crearía una autorreferencia sin solución finita.

El provisional es un wrapper hermano del destino, se crea con modo 0700 y
conserva `INCOMPLETE`; su subdirectorio `payload`, también 0700, no contiene el
marcador y se publica mediante `renameat2(RENAME_NOREPLACE)`. El recorrido
no enumera el árbol ni modela hardlinks, inodos, symlinks o ventanas TOCTOU como
entradas hostiles. Mantiene cierre, tamaño, SHA-256, temporales propios y
atomicidad frente a errores e interrupciones ordinarias.

Las pruebas de proceso construyeron y comprobaron tres árboles reales:

- `complete`: manifiesto, TOML copiado, `effective-config.json` y FASTA;
- `failed`: el CLI/orquestador real salió con código 2 y `GPS-INPUT-001`, y
  publicó un manifiesto válido con diagnóstico, TOML catalogado y la reducción
  solicitada aún `incomplete`;
- `INCOMPLETE`: provisional privado conservado tras SIGKILL, sin destino final.

Una regresión detuvo deliberadamente el flujo justo después del rename y antes
de limpiar el wrapper: el destino contenía el manifiesto pero nunca
`INCOMPLETE`; el marcador permaneció únicamente en el wrapper exterior. Una
carrera sincronizada de dos procesos produjo un único destino, un único
éxito y un perdedor con salida 5 y `GPS-IO-003`; su provisional conservó
`INCOMPLETE`. Un destino preexistente conservó intacto su fichero testigo.

## Oráculos independientes

- CPython/jsonschema 4.10.3 validó Draft 2020-12 mediante
  `tests/external_jsonschema_validator.py` y
  `tests/external_manifest_validator.py`.
- El oráculo externo aceptó manifiestos `complete` y `failed` y rechazó JSON
  truncado, campo desconocido, enlace ausente, catálogos duplicados y categorías
  incompatibles.
- El publicador relee `effective-config.json` con un validador Rust mínimo y
  cruza el conjunto exacto de referencias, la representación completa de cada
  reducción y las clases de artefacto con catálogo y manifiesto. También
  recalcula suma de composición y tamaño total. Las regresiones mutan cada
  campo, referencia huérfana, suma, tamaño, truncado, clase e IDs.
- Si ese documento producido es inválido, el orquestador lo elimina y
  descataloga antes de publicar el fallback `failed`; el árbol real no contiene
  `effective-config.json` inválido ni su ID. `GPS-FMT-006` conserva categoría
  FMT, significado catalogado y salida 1. Un gate recorre todos los códigos
  activos de `src` y contrasta código, categoría, significado y salida contra
  `diagnostics-v2.tsv`.
- La configuración efectiva y el manifiesto no se aceptan como prueba de sus
  propias declaraciones: el publicador relee los FASTA y mapas enlazados,
  reutiliza los validadores canónicos de referencia/reducción y reconstruye la
  generación, selección, referencia derivada y mapa. Regresiones con hashes
  recalculados rechazan cambios correlacionados de tamaño de región, IDs,
  longitud/tamaño, composición y mapa.
- Un test del orquestador altera un FASTA válido y recalcula su entrada de
  catálogo antes del cierre. La ejecución publica `failed` con `GPS-FMT-006` y
  elimina tanto `effective-config.json` como su ID, en lugar de respaldar los
  bytes alterados con un documento también producido.
- Todo diagnóstico de un manifiesto `failed` debe existir en
  `diagnostics-v2.tsv` y conservar su significado canónico. El validador Rust y
  el oráculo Python rechazan `GPS-FMT-999` y un mensaje alterado, y aceptan el
  diagnóstico positivo catalogado.
- El objetivo efectivo se reconstruye desde la copia TOML y aritmética decimal
  exacta: `mode`, `declared` y `bases` no pueden mutarse de forma correlacionada.
  La regresión `reduction_percent=99.9` rechaza los documentos que conservan
  indebidamente 13 bases.
- Si falla una validación física, el fallback `failed` es conservador: publica
  solo el TOML revalidado y el diagnóstico; no conserva FASTA, mapas,
  referencias ni configuración efectiva dudosos en fichero, catálogo, enlaces
  o categorías.
- Las categorías no son una partición arbitraria: `requested` se deriva de los
  FASTA y mapas de reducciones, `minimum` contiene el complemento permitido de
  F1 y `defaulted`/`disabled` permanecen vacías. Un intercambio correlacionado
  entre `minimum` y `requested` se rechaza.
- El validador Rust acepta y verifica el catálogo completo
  `diagnostics-v2.tsv`, mientras el productor mantiene su subconjunto activo.
  Rust y Python aceptan `GPS-DOMAIN-003` con su significado canónico y rechazan
  códigos o mensajes inventados.
- La copia TOML gobierna el contrato efectivo completo: procedencia, semilla y
  origen, fuente de referencia, ID, composición, orden/clase/longitud de cada
  secuencia y todos los campos de cada reducción. Las regresiones sustituyen el
  TOML por alternativas válidas con otra semilla, región, referencia, clase o
  composición, recalculan tamaño/SHA y exigen rechazo.
- La clasificación es globalmente disjunta. Además de comparar roles exactos,
  Rust rechaza que un ID aparezca en dos categorías o que una reducción reutilice
  el mismo FASTA como fuente y derivado; el oráculo Python coincide.
- `execution_id` se deriva mediante una única función compartida desde la raíz
  efectiva y el digest canónico de los bytes TOML. Una regresión mezcla dos
  ejecuciones CSPRNG válidas y otra cambia solo un comentario del TOML; ambas se
  rechazan aunque se recalculen los SHA del catálogo.
- El oráculo Python contiene la desigualdad directa entre FASTA fuente y
  derivado, por lo que una reducción autocíclica ya no depende de que otra
  comprobación la intercepte.
- `INCOMPLETE` está reservado como nombre raíz del marcador del wrapper. La API
  de escritura, el parser Rust, JSON Schema y el corpus externo impiden
  catalogarlo dentro del payload final.
- GNU `sha256sum` 9.4 comprobó tamaño y digest de todos los ficheros de un árbol
  real; las regresiones de integridad detectaron cambio de un byte y truncado.
- `publication_process::configuration_copy_is_byte_exact_linked_and_matches_external_sha256`
  recorre el CLI real y compara los bytes del TOML original con su copia; además
  resuelve el enlace `configuration_input` y contrasta clase, ruta, tamaño y
  digest mediante `sha256sum`. La matriz TEST-REQ-SAL-03 apunta a este testigo.

## Puertas ejecutadas

Todas terminaron con código 0:

```text
cargo fmt --all -- --check
cargo clippy --all-targets --all-features --locked -- -D warnings
cargo test --all-targets --all-features --locked
cargo test --doc --locked
cargo doc --no-deps --locked
cargo build --release --locked --target x86_64-unknown-linux-gnu
cargo metadata --locked --format-version 1
cargo tree --locked -e features
cargo audit --no-fetch
git diff --check
```

La suite enumeró 144 casos: 143 se ejecutaron correctamente y el helper que
solo se invoca en subprocesos quedó ignorado en el proceso padre. El doctest
`compile_fail` también pasó.

`cargo audit --no-fetch` cargó 1216 avisos, examinó los 65 paquetes del lock y
terminó con código 0. Advirtió que no pudo tomar el lock del índice local; no
informó vulnerabilidades. `jsonschema` ya no aparece en `Cargo.toml`,
`Cargo.lock` ni el árbol de características.

## Alcance negativo comprobado

El manifiesto y los árboles reales no contienen `units`, eventos, conjuntos,
`resolution-evidence`, capabilities, snapshots de workspace ni inventarios de
inodos. No se inició F1.5 ni se añadió biología futura.
