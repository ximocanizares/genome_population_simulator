# Redactar texto técnico

## Objetivo

Conseguir que el lector entienda el mensaje una sola vez sin perder precisión
técnica. Adaptar la profundidad al público y a la decisión que el texto debe
permitir tomar.

## Preparación

Antes de escribir, identificar:

1. quién leerá el texto;
2. qué sabe ya esa persona;
3. qué debe comprender, decidir o hacer al terminar;
4. qué hechos están confirmados y qué partes son propuestas o inferencias;
5. qué extensión y formato necesita realmente el contenido.

Para este proyecto, asumir conocimientos habituales de genética. Explicar los
conceptos de programación, arquitectura, pruebas y estadística avanzada que
sean necesarios para interpretar la decisión.

## Fidelidad

- Conservar el significado de requisitos, resultados y restricciones.
- No inventar causas, beneficios, cifras, citas ni consenso.
- Identificar expresamente una inferencia y explicar la evidencia que la apoya.
- Citar rutas, secciones, comandos o fuentes cuando se afirme algo verificable.
- Distinguir hecho, requisito, recomendación, ejemplo, decisión pendiente y
  trabajo futuro.
- Corregir ambigüedades sin convertir una posibilidad en una obligación.

## Redacción

- Escribir en castellano y mantener términos oficiales cuando sean más precisos.
- Empezar por la conclusión, el resultado o la idea que organiza la sección.
- Usar voz activa, verbos concretos y frases de longitud moderada.
- Dedicar cada párrafo a una idea principal.
- Explicar primero la función de un concepto y después su nombre técnico.
- Definir términos ambiguos y siglas no habituales en la primera aparición.
- Usar un único término para cada concepto y evitar sinónimos decorativos.
- Preferir palabras comunes a formulaciones abstractas o burocráticas.
- Eliminar repeticiones, introducciones vacías y conclusiones que solo repitan.
- Incluir el detalle técnico justo para comprender o verificar el mensaje.

## Estructura y formato

Elegir la estructura más pequeña que haga visible la relación importante:

- prosa breve para una idea o explicación lineal;
- lista para elementos equivalentes o pasos independientes;
- tabla para comparar campos o alternativas repetidas;
- diagrama para flujos, jerarquías o dependencias difíciles de seguir en prosa;
- ejemplo para aclarar una regla, nunca para sustituirla.

Usar títulos descriptivos. No fragmentar un texto corto en muchas secciones ni
convertir cada frase en una viñeta.

En ejemplos genómicos, declarar referencia, coordenadas, alelos, ploidía o fase
cuando sean necesarios para evitar interpretaciones distintas.

## Explicar decisiones y conceptos complejos

Seguir este orden cuando resulte útil:

1. conclusión o definición sencilla;
2. motivo práctico;
3. funcionamiento o regla precisa;
4. ejemplo mínimo;
5. límite, excepción o consecuencia.

No presentar una opinión como propiedad universal. Si existen alternativas,
compararlas con el criterio relevante para este proyecto y no con ventajas
genéricas.

## Revisión

Antes de entregar:

- comprobar que la primera parte comunica el resultado principal;
- verificar que el público puede entender todos los términos necesarios;
- confirmar que ninguna simplificación cambia el significado;
- separar con claridad hechos, decisiones, propuestas y futuro;
- revisar coherencia de nombres, unidades, referencias y ejemplos;
- eliminar contenido que no ayude a comprender, decidir, ejecutar o comprobar;
- leer las frases largas y dividir las que contengan varias ideas;
- confirmar que listas, tablas o diagramas aportan claridad real.

El texto está listo cuando es preciso, verificable y tan breve como permite su
propósito, no tan breve como para ocultar una condición importante.
